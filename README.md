# Монитор цен OneTwoTrip

## Запуск production-копии через Docker Compose

Создайте `.env` из `.env.example` на сервере. Задайте `POSTGRES_PASSWORD` случайной строкой из букв и цифр, `TELEGRAM_BOT_TOKEN` и `TELEGRAM_OWNER_CHAT_ID` (или `TELEGRAM_CHAT_ID`). Docker Compose собирает `DATABASE_URL` из `POSTGRES_USER`, `POSTGRES_PASSWORD` и `POSTGRES_DB`; PostgreSQL доступен только контейнерам Compose. Не добавляйте `.env` в образ или репозиторий.

```bash
docker compose up -d --build
docker compose run --rm flight-monitor python -m flight_monitor history
```

Сервис `flight-monitor` запускает `python -m flight_monitor bot`. Сервис `scheduler` вызывает существующий `check_runner` каждые `CHECK_INTERVAL_MINUTES` минут (по умолчанию 60); первый автоматический поиск начинается после первого интервала. Команда `history` открывает PostgreSQL и применяет миграции без поиска билетов. Для отдельной ручной проверки используйте `docker compose run --rm flight-monitor python -m flight_monitor check`. Cloud deployment здесь не выполняется.

Один запуск проверяет цены **прямых авиарейсов LED → MOW на 04.11.2026** для одного взрослого в экономклассе, сохраняет историю и завершает процесс. Источник цен только OneTwoTrip. Маршрут и дата задаются окружением. Поисковая цена может отличаться от окончательной цены при покупке.

## Как устроено

```text
Playwright/Chromium → обычная страница поиска OneTwoTrip
  → JSON-ответ /_avia-search-proxy/search/v3
  → parser → FlightOffer (Decimal)
  → MonitorService → SQLite или PostgreSQL repository
                       → Telegram при подтверждённом снижении
```

**Выбран Playwright**, потому что простой Python HTTP-запрос к внутреннему endpoint без cookies и особых заголовков получил HTTP 403. Подбор браузерных заголовков не предпринимался. Playwright открывает обычную страницу в новом headless-контексте и читает именно сетевой JSON-ответ, который использует frontend. Разбор DOM не нужен. Версию и параметры внутреннего endpoint задаёт действующая страница; приложение не закрепляет `cryptoTripsVersion`. Ответ с `fromCache=true` или неизвестным статусом кэша отвергается. В случае CAPTCHA, HTTP 403/429, таймаута или изменения JSON-схемы проверка завершается ошибкой без подмены свежей цены старой.

Программа проверена с разрешённым пользователю личным сценарием автоматического поиска OneTwoTrip. Храните условия своего разрешения и соблюдайте его частоту. Приложение не делает бронирований и не обходит проверки доступа.

## Установка

Python 3.11+:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:PLAYWRIGHT_BROWSERS_PATH = (Join-Path (Get-Location) '.pw-browsers')
.\.venv\Scripts\python.exe -m playwright install chromium
```

На Linux/macOS используйте `.venv/bin/python`. Для Linux в контейнере понадобятся системные зависимости Chromium: команда `python -m playwright install --with-deps chromium` в образе с подходящими правами либо официальный Playwright Python image той же версии, что в `requirements.txt`. Скачанный браузер в `.pw-browsers` автоматически обнаруживается в локальном проекте; иначе Playwright использует свой стандартный каталог браузеров. GUI и запущенный домашний компьютер не требуются.

## Настройка

Пример значений — в [`.env.example`](.env.example). При локальном запуске приложение автоматически загружает `.env` из корня проекта. Скопируйте `.env.example` в `.env` и заполните нужные значения; `.env` исключён из git. Уже заданные переменные окружения ОС имеют приоритет над `.env`. По умолчанию заданы LED, MOW, 2026-11-04, 1 взрослый, эконом, прямые рейсы, ожидание повторной проверки 30 секунд и `data/flight_monitor.sqlite3`. Можно переопределить `ORIGIN`, `DESTINATION`, `DEPARTURE_DATE`, `ADULTS`, `CABIN_CLASS`, `DIRECT_ONLY`, `RECHECK_DELAY_SECONDS`, `DATABASE_PATH` или `DATABASE_URL`. Проверенный браузерный flow пока поддерживает 2026 год, 1 взрослого, эконом и прямые рейсы; другие параметры отклоняются явно.

Для Telegram создайте бота через BotFather, получите chat ID и задайте `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` в локальном `.env` или переменных окружения ОС. Вместо `TELEGRAM_CHAT_ID` можно задать `TELEGRAM_OWNER_CHAT_ID`. Если настройки отсутствуют, поиск и история работают без отправки Telegram. Не помещайте реальные секреты в `.env.example` и репозиторий. `BROWSER_CHANNEL=chrome` допускается, если хотите использовать установленный Chrome вместо Chromium Playwright. `BROWSER_TIMEOUT_SECONDS` по умолчанию 60.

Для локального тестирования можно добавить в `.env` `TELEGRAM_NOTIFY_EVERY_RUN=true`: после каждого успешного `check` бот отправит отчёт по текущему поиску. Он показывает до 10 физических рейсов с минимальными ценами без зарегистрированного багажа и с ним, два топа по времени вылета и лидеров обеих категорий. Изменение цены каждого лидера сравнивается с тем же физическим рейсом и той же категорией в предыдущем успешном поиске. Если достоверного признака багажа нет, категория остаётся неизвестной и её цена в соответствующей колонке не появляется. По умолчанию настройка `false`, и уведомления отправляются только при подтверждённом новом историческом минимуме. Ошибка поиска не вызывает отправку отчёта; `--dry-run` отключает все Telegram-сообщения.

## Запуск

```powershell
.\.venv\Scripts\python.exe -m flight_monitor check --dry-run
.\.venv\Scripts\python.exe -m flight_monitor check
.\.venv\Scripts\python.exe -m flight_monitor history
.\.venv\Scripts\python.exe -m flight_monitor telegram-test
```

`--dry-run` выполняет **реальный поиск и сохраняет его в БД**, но не отправляет Telegram. Первый успешный поиск устанавливает baseline без уведомления о новом минимуме; при `TELEGRAM_NOTIFY_EVERY_RUN=true` он всё же отправляет информационную сводку. В последующих запусках только цена ниже подтверждённого исторического минимума запускает повторный свежий поиск через `RECHECK_DELAY_SECONDS`. Подтверждение требует того же физического рейса и цены не выше первой находки; временные `offer_id` между поисками не сопоставляются. Оба наблюдения сохраняются. При неподтверждённом снижении исторический минимум не меняется.

`telegram-test` отправляет одно сообщение «Flight Monitor: Telegram работает». При отсутствии Telegram-настроек команда завершается с кодом 1 и показывает, какие переменные нужно задать.

CLI показывает до 10 **физических рейсов** из текущего поиска с отдельными ценами без багажа и с багажом; лидеры обеих категорий включаются в таблицу. Все предложения и тарифные варианты сохраняются в выбранной БД. Денежные суммы хранятся текстом Decimal без потери копеек; в Telegram они округляются до целого рубля. Старые записи без признака багажа остаются в истории и считаются категорией `UNKNOWN`. При успешном подтверждении цена становится историческим минимумом даже при отключённом Telegram; статус попытки уведомления сохраняется отдельно.

## Stage 5A: база данных и Telegram-бот

Локально остаётся SQLite (`DATABASE_PATH` либо `DATABASE_URL=sqlite:///...`). Для production подготовлен PostgreSQL adapter: `DATABASE_URL=postgresql://user:password@host:5432/database`. Новые таблицы создаются идемпотентно; существующая SQLite-история сохраняется. Тесты и fixture хранятся в исходной рабочей папке и не входят в эту production-копию.

При первом запуске `bot` или `check` владелец автоматически регистрируется в БД по `TELEGRAM_OWNER_CHAT_ID`; если он не задан, используется прежний `TELEGRAM_CHAT_ID`. Повторный запуск не создаёт дубль. Только владелец может отправить `/invite` и получить одноразовую ссылку, действующую 24 часа. Новый пользователь открывает ссылку в личном чате с ботом; обычный `/start` без ссылки доступа не даёт. `/users` показывает владельцу список пользователей. Одновременно могут быть активны не более трёх пользователей, включая владельца (`MAX_TELEGRAM_USERS=3`).

Зарегистрированный пользователь отправляет `/check` или нажимает `🔄 Проверить цены сейчас`. Бот сразу подтверждает запрос, запускает поиск в одном фоновом worker и после успеха отправляет полный Rich Markdown отчёт запросившему. `MANUAL_CHECK_COOLDOWN_SECONDS=180` предотвращает повторные нажатия отдельно для каждого пользователя. Общая блокировка БД с `CHECK_LOCK_TTL_SECONDS=600` не допускает одновременного ручного и планового поиска; занятый плановый `check` завершается со статусом `skipped_locked`. Подтверждённое ценовое уведомление рассылается остальным активным пользователям, если оно возникло при ручной проверке, а обычный плановый запуск рассылает его всем активным пользователям.

Для локального приёма Telegram-команд запустите в отдельной консоли:

```powershell
.\.venv\Scripts\python.exe -m flight_monitor bot
```

Команда `python -m flight_monitor check` остаётся конечным процессом. `bot` использует long polling; периодические проверки запускает отдельный контейнер. Dockerfile содержит Python, Playwright и Chromium; `.env` исключён из образа. Развёртывание в Yandex Cloud и webhook здесь не выполняются.

Внутренний формат OneTwoTrip может измениться. При ошибке схемы приложение не уведомляет о цене, не обновляет подтверждённый минимум и завершается с кодом 1. При отсутствии рейсов завершается успешно со статусом `empty`, сохраняя существующую историю. Для гарантии цены покупки нужно отдельно проверить её на стороне продавца.
